# 定位計算程式 — 模擬程式 規格

> 本檔定義「模擬程式」：**代替真實感測器，持續產生 §C 的 RSSI 封包**，讓定位計算程式與 GUI
> 在**沒有樹莓派、沒有 MQTT broker、沒有真手機**的情況下也能被驗證。
> 對應介面規格見 [[2.2.1 定位計算程式 — 跨程式介面規格]] §C；計算核心見 [[2.2.2 定位計算程式 — 計算]]。

---

## 1. 目的與定位

| 項目 | 說明 |
|------|------|
| 為什麼要它 | 開發時不可能隨時有真感測器/真手機；模擬程式讓整條資料流「可重現、可調參數」 |
| 它模擬誰 | **感測器（樹莓派）** —— 也就是 §C 的發送方 |
| 它模擬什麼 | 「某些學號在某些感測器上被量到的 RSSI」隨時間的變化 |
| 它不模擬 | XOR 解密、BLE 掃描、MQTT 連線、OTP 驗證（那些是感測器/Node 的職責） |
| 它如何進入系統 | 與真實資料**走同一條路徑**：餵給 `PersonTracker.ingest()`；不繞過引擎 |

> 關鍵原則：模擬器**只用現成的對外介面**（GUI 的 `/api/ingest` 或引擎的 `ingest()`），
> 因此「模擬能跑」＝「真資料也能跑」。

## 2. 兩種提供形式

| 形式 | 位置 | 何時用 |
|------|------|--------|
| **A. 命令列模擬器** | `tools/simulate_receivers.py` | 想在終端看「真值 vs 算出」對照、或做 CI/批次測試 |
| **B. GUI 內建模擬器** | GUI 監看分頁右側面板（後端 `Simulator`） | 想用滑桿即時調參數、眼睛看圓點怎麼動 |

兩者**共用同一套數學與參數語意**（見 §3、§4），差別只在操作介面。

## 3. 模擬數學（核心）

模擬器為每位模擬學生維護一個**真實位置** `(x_true, y_true)`（公尺），
每個 tick 對每臺使用中的感測器，依「距離 → RSSI」的反函式產生一筆量測：

```
d        = max( hypot(x_true - sx, y_true - sy), 0.3 )      # 公尺，0.3 為避免 log10(0)
rssi_raw = A_s - 10 * n_s * log10(d)                        # 該臺自己的 n_s / A_s
rssi     = rssi_raw + N(0, noise²)                          # 加高斯雜訊
```

| 符號 | 意義 | 來源 |
|------|------|------|
| `sx, sy` | 該感測器位置 | config 的 `ScannerConfig.pos_m` |
| `n_s` | 該感測器 path-loss exponent | config（**每臺一份**） |
| `A_s` | 該感測器 1m 處參考 RSSI (dBm) | config（**每臺一份**） |
| `noise` | RSSI 高斯雜訊標準差 (dBm) | 參數，見 §4 |
| `N(0, σ²)` | 常態分布亂數 | 標準庫 `random.gauss` |

> 這是 [[2.2.2 定位計算程式 — 計算]] §3.1 「rssi → 距離」的**反函式**。
> 因此 `noise = 0` 時，理論上引擎應能還原到幾乎精準；`noise` 越大越考驗演算法。
> 特別注意：模擬器用的是 config 中**每臺真實的 (n, A)**；若故意在別處把某臺 `(n,A)` 設錯，
> 就能重現「參數未校正 → 系統性偏移」的情境（供 §7 校正驗證用）。

## 4. 參數定義（兩種形式共用語意）

| 參數 | 型態 | 預設 | 說明 |
|------|------|------|------|
| `students` | int | 2 | 模擬人數。自動配學號 `11012345, 11012346, …`（每次啟動重配） |
| `noise` | float (dBm) | 2.0 | RSSI 高斯雜訊 std。`0` = 完美訊號 |
| `motion` | enum | `circle` | 移動模式：`circle` / `walk` / `static`（見 §5） |
| `speed` | float | 0.6 | `walk` = 每步最大位移(m)；`circle` = 角速度(rad/s) |
| `interval` | float (s) | 0.5 或 1.0 | 每個 tick 的間隔，亦為模擬時間步 |
| `scanner_count` | int | 2 | **使用前幾臺**感測器（2 ⇒ 雙邊；≥3 ⇒ 多邊）。至少 2 |
| `rounds` | int | 0 | 命令列版才有；跑幾輪後停止，`0` = 無限 |
| `quiet` | bool | False | 命令列版才有；只送資料、不印對照 |
| `gui` / `config` | str | — | 命令列版：GUI 位址；教室設定檔路徑 |
| `sink` | enum | `direct` | **輸出目標**：`direct`（直接餵引擎）或 `mqtt`（publish 規格 §C 封包）。見 §4.2 |
| `mqtt_host` | str | `127.0.0.1` | `sink='mqtt'` 時的 broker 位址 |
| `mqtt_port` | int | `1883` | broker 埠（wss 則為 443，需另行擴充 TLS） |
| `mqtt_topic` | str | `mcu/indoor-location` | base topic；實際發到 `{topic}/receivers/{scanner_id}` |
| `mqtt_username` / `mqtt_password` | str | "" | 選填；有值才帶認證 |

**限制與容錯**
- `students ≥ 1`；`scanner_count ≥ 2`（<2 無法定位，模擬器會拒絕/跳過）。
- `scanner_count` 超過 config 實際臺數時，取用**全部可用臺數**。
- `interval` 有下限（GUI 端 0.05s）避免忙迴圈。

### 4.1 命令列參數對應（`tools/simulate_receivers.py`）
| CLI | 等同 §4 參數 |
|-----|--------------|
| `--students 11012345,11012346` | `students`（**此版由使用者明確給學號清單**） |
| `--noise` | `noise` |
| `--motion` | `motion` |
| `--speed` | `speed` |
| `--interval` | `interval` |
| `--only-scanners 1,2` | `scanner_count` 的**明確版本**（指定哪幾臺，非「前 N 臺」） |
| `--rounds` / `--quiet` | 同 §4 |
| `--gui` / `--config` | 目標與設定來源 |

> 差異：GUI 版用「人數 → 自動配號」與「前 N 臺」；CLI 版用「明確學號清單」與「指定哪幾臺」。

### 4.2 輸出目標 `sink`（本規格重點）

模擬器可有兩種把量測**送進定位程式**的方式：

| sink | 行為 | 驗證到什麼 | 依賴 |
|------|------|-----------|------|
| `direct` | 直接呼叫 `PersonTracker.ingest()`（同一個 Python process） | 只驗證**計算核心**（雙邊/多邊/Kalman） | 無 |
| `mqtt` | 組 §C payload → `publish` 到 `{topic}/receivers/{scanner_id}` | 端到端：**broker 連線、topic 約定、JSON 欄位、`mqtt_in` 解析** | `paho-mqtt` + broker |

> **為什麼要兩種**：`direct` 快、免環境，適合調演算法；`mqtt` 才能抓出「欄位拼錯、topic 不對、連線失敗」這類只有真實傳輸才會浮現的問題。
> 目前 CLI 版（`tools/simulate_receivers.py`）為 `direct`；§4.2 的 `sink` 由 **GUI 內建模擬器** 提供切換。

**連線方式（`sink='mqtt'` 時）**
| 參數 | 值 | 說明 |
|------|-----|------|
| `mqtt_transport` | `tcp` / `websockets` | 原生 MQTT 或 ws/wss |
| `mqtt_tls` | bool | 開 ⇒ `mqtts` / `wss` |
| `mqtt_ws_path` | str | websockets 的 path（Cloudflare 常見 `/`） |

- **本機 mosquitto（原生）**：transport=`tcp`、tls=關、port=`1883`
- **Cloudflare Tunnel + WSS**（例如 `broker.stevehsiao.com`）：
  transport=`websockets`、tls=**開**、port=`443`、path=`/` → 即 `wss://host:443/`
  （GUI 面板有「套用 Cloudflare wss 預設」一鍵鈕）

**CONNACK 處理**
- `rc=0` 成功；`rc=5` = 未授權（帳密錯誤）。
- 啟動時會**等 CONNACK**：非 0 或逾時 → `POST /api/sim/start` 回 `400`，訊息如
  `"CONNACK rc=5（未授權：帳號/密碼錯誤）"`，**不會靜默失敗**。

**payload 組裝（sink='mqtt' 時）** — 欄位與 §C 完全相同：
```json
{
  "student_id": "11012345",
  "OTP": "",
  "mac": "",
  "rssi": -72.0,
  "scanner_id": 1,
  "time": ""
}
```
- `mac` 留空／僅除錯用途，**不作為識別**（與 §C 註記一致）。
- `OTP`／`time` 模擬器可留空；真感測器會填。
- 發布 QoS = 1。

**錯誤處理**：`sink='mqtt'` 啟動時先連 broker，若 `paho-mqtt` 未安裝或連線失敗 →
`POST /api/sim/start` 回 `400 {"status":"failed","reason":"sim_error","message":"…"}`，**不進入 running**。

## 5. 移動模式 `motion`

| 值 | 行為 | 用途 |
|----|------|------|
| `static` | 位置固定不動 | 單看**雜訊**對定位的影響（人沒動，圓點應只小幅抖動） |
| `walk` | 每步 x,y 各隨機 ±`speed` 公尺；限制在教室內（留 0.3m 邊界） | 最接近真人走動，測**追蹤收斂** |
| `circle` | 繞房間中心畫圓：半徑 `min(W,H)/3`，角度 = `t × speed + phase` | 肉眼**盯著一顆圈圈跑**，確認圓點是否跟著 |

- 初始位置：第 i 位學生 `x = 2.0 + 2.5·i`，`y = 教室高/2`。
- `circle` 模式每位學生帶不同相位 `phase = i·0.9`（並略異半徑），**避免多人重疊**。
- 座標一律夾在 `[0.3, 房間尺寸-0.3]` 內（`walk`）。

## 6. GUI 內建模擬器的介面（形式 B）

### 6.1 後端 API（`locator/gui/server.py`）

| Method | Path | 用途 |
|--------|------|------|
| `POST` | `/api/sim/start` | 啟動／重啟模擬。body = §4 參數（缺省沿用先前值） |
| `POST` | `/api/sim/stop` | 停止模擬 |
| `GET`  | `/api/sim/status` | 取得目前狀態（含 `running` 與參數） |

`POST /api/sim/start` body 範例：
```json
{
  "students": 3,
  "scanner_count": 2,
  "motion": "walk",
  "speed": 0.6,
  "noise": 1.5,
  "interval": 0.3,
  "sink": "mqtt",
  "mqtt_host": "127.0.0.1",
  "mqtt_port": 1883,
  "mqtt_topic": "mcu/indoor-location",
  "mqtt_username": "",
  "mqtt_password": ""
}
```
回應：
```json
{
  "status": "ok",
  "sim": { "running": true, "students": 3, "noise": 1.5, "motion": "walk",
           "scanner_count": 2, "speed": 0.6, "interval": 0.3,
           "sink": "mqtt", "mqtt_host": "127.0.0.1", "mqtt_port": 1883,
           "mqtt_topic": "mcu/indoor-location",
           "people": ["11012345","11012346","11012347"], "pub_error": null }
}
```
失敗（例如 `sink='mqtt'` 但無 paho 或連不上）→ `400`：
```json
{ "status": "failed", "reason": "sim_error", "message": "需要 paho-mqtt（pip install paho-mqtt）" }
```
另外 `GET /api/state` 會附帶 `sim` 欄位（狀態 + 參數 + `pub_error`），供監看分頁顯示。

### 6.2 前端面板（監看分頁右側）
- 可調：**學生人數、感測器數、模式、速度、雜訊(std)、更新間隔**。
- **輸出目標**下拉：`direct` / `mqtt`；選 `mqtt` 時展開 broker host、port、base topic、帳密欄位。
- 按鈕：**開始 / 停止**；狀態列顯示「執行中 ● N人 / M臺 / 模式 / 雜訊 X dBm / 輸出:direct|MQTT→host:port」。
- **執行中調整任一參數 → 立即重新套用**（自動重啟模擬）。
- 面板操作等同呼叫 §6.1 的 API。

### 6.3 與其他 API 的互動
- `POST /api/config`（儲存教室設定）會**自動停止模擬**，因為感測器幾何已改變。
- `POST /api/clear`（清空追蹤）不影響模擬器本身，模擬仍在跑會立刻重新累積資料。

## 7. 主迴圈（形式 A；形式 B 為等效執行緒）

```
讀 config → 取得 room 尺寸、各臺 pos_m/n/A
決定 used = 指定/前 N 臺感測器（需 >= 2）
t = 0
while not stop:
    t += interval
    1) 依 motion/speed 移動每位學生的真值 (x,y)
    2) for 每位學生 × for 每臺 used：
           d = hypot(x-sx, y-sy)
           rssi = A_s - 10·n_s·log10(d) + gauss(0, noise)
           送出量測 → tracker.ingest(scanner_id, student_id, rssi)
    3) （非 quiet）讀回 /api/state，印出「真值 vs 算出」對照
    4) sleep(interval)  ；rounds 到就停
```

**對照輸出格式（形式 A）**
```
[   3] 11012345 真(7.5,6.2) 算(8.5,6.3) | 11012346 真(7.0,6.5) 算(8.4,6.5)
```
- 「真」= 模擬器內部真實位置；「算」= 引擎經 GUI `/api/state` 解出的位置。
- `算(尚無)` 表示該生還沒湊到 ≥2 臺資料。

## 8. 驗收

1. **單人靜止、雜訊 0、兩臺** → 「算」應幾乎等於「真」（誤差趨近 0）。
2. **單人靜止、雜訊拉大(6~10 dBm)** → 圓點在原位附近抖動，不應亂跳到大範圍。
3. **改成 `walk`/`circle`** → 圓點**跟著移動**且平滑（Kalman 生效），無爆走。
4. **多人（≥3）** → 每人一顆不同色圓點、各自獨立移動，不互相干擾。
5. **感測器數切 2 vs 3** → 方法由 `bilateration` 變 `multilateration`（GUI 右欄可見）。
6. **執行中改參數** → 立即生效（人數/雜訊/模式切換後行為當場改變）。
7. **停止** → 不再有新資料，圓點位置凍結。
8. **超出教室的座標** → GUI 以紅色 ⚠ 標示（模擬器本身不會產生教室外真值，
   但雜訊/幾何不良可能讓引擎解到教室外，這正是要觀察的）。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install paho-mqtt amqtt
```

> 它產生的資料格式與真實 §C 完全相同，因此可用來做開發、回歸測試與教學示範。
